# Awards strategy — proposal

Aim for the High School Grand Prize with a coherent, student-led contribution. The [official-rule evidence review](11-igem-rule-evidence.md) distinguishes the Grand Prize, Gold medal and Special Awards. A provisional three-award route is Model + Software + Integrated Human Practices; village and nominations remain team choices, checked against 2027 rules when available. Current rules require iGEM GitLab hosting and an OSI-approved license for Software; Software & AI Village teams are ineligible for that award.

| Proposed priority | Evidence required | Current gap |
| --- | --- | --- |
| Best Software | Useful reproducible tool, evaluation, documentation and external feedback | Evaluator exists; no validated design model |
| Best Model | Explicit assumptions, independently checked predictions and impact on decisions | WIsH produced a decision-relevant negative result; next-method evaluation and human source review pending |
| Integrated Human Practices | Relevant engagement that changes project design and is evaluated afterward | Questions can be prepared; engagement and resulting changes not yet recorded |

Measurement is an alternative if a substantial measurement contribution emerges, including a suitably validated computational one. It should replace a proposed selection on the strength of the work, rather than expand the three-award plan. [Prior art and innovation hypotheses](12-prior-art-and-innovation.md) connect the platform ambition to testable contributions.

Best Part Collection is a conditional alternative if characterized parts are actually produced. Basic/Composite Part judging uses Registry entries under current guidance; check the specific collection criteria too. Repository Markdown is preparation, not a substitute for Registry documentation. Do not claim every Part-related criterion is identical.

Village proposal: review Foundational Advance, if offered in 2027, against the final deliverable. A software-only or sensor-focused result may warrant a different choice. Keep `parts/` ready from the beginning; no invented Registry IDs. The October wiki/Registry migration target is internal planning, not a verified freeze deadline.
